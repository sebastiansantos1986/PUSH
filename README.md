# PUSH — Proactive Update Scheduling Helper

**Developer: Sebastian Santos** · [MIT license](LICENSE) · Attribution ID: `PUSH-DEV-SEBASTIAN-SANTOS`

PUSH discovers eligible macOS updates, keeps users informed, and applies an administrator’s reviewed policy. **JamfCheckIn** is the employee menu-bar app. **PUSH Admin** stays on IT workstations and builds configured client installers.

**Current test release: engine 1.11.0 · Admin 1.3.0 · JamfCheckIn 1.1.1 · macOS 14+ · Apple Silicon and Intel.**

[Downloads](https://github.com/sebastiansantos1986/PUSH/releases/tag/v1.11.0-admin-1.3.0) · [Admin builder guide](docs/ADMIN-BUILDER-GUIDE.txt) · [Client installation](docs/CLIENT-INSTALL-GUIDE.txt) · [Wiki](https://github.com/sebastiansantos1986/PUSH/wiki)

## Choose the right installer

| Installer | Destination | Behavior |
| --- | --- | --- |
| **PUSH-Admin-1.3.0.pkg** | IT workstation | Configuration, setup suggestions, safe previews and complete client builder. Does not activate PUSH. |
| **PUSH-Client-1.11.0.pkg** | Employee/pilot Mac | Engine, popups and JamfCheckIn. Preserves existing YAML; fresh installs use safe defaults. Both monitors stay paused. No Admin app. |
| **PUSH-Major-Offer-Only.pkg** | Optional preview pilot | Isolated simulation/notices and presentation settings; paused/dry-run. No JamfCheckIn, enforcement UI or live optional upgrade. |
| **PUSH-Configured-Client.pkg** | Generated by Admin for your Macs | Engine, JamfCheckIn, reviewed YAML and selected images. Replaces previous YAML after backup; installation mode is explicitly selected at build review. No Admin app. |

The published binaries are **ad-hoc signed local test builds**, and installers are unsigned. Developer ID signing, notarization and an enrolled managed pilot remain before production rollout. Building and offline verification did not install or launch PUSH, enable monitoring, change wallpaper, perform registration, download/install updates or restart a Mac.

## New popup experience and major-only package

**Engine 1.11.0 / Admin 1.3.0** adds configurable width/height, banner image/text and a logged-in-user greeting such as `Hello {fullName}` for the major-offer demo and standalone notices. Existing required-update windows keep their own layouts.

- **Major Upgrade (Debug):** one resizable window simulates the offer, download, preparation and restart choice. It never sends an installation or restart request.
- **Single Popups:** Regina-inspired informational alerts/toasts; buttons return acknowledgement, close or timeout without running commands. Regina's password/input/script features were not merged.
- **Apple hardware support:** fresh Apple device/board lists distinguish supported, unsupported and unverified. A confirmed unsupported result blocks a required major-upgrade attempt before download; unfamiliar/stale results stay unverified.
- **Major offer only (preview):** Admin can build a package containing the CLI, isolated demo, notices, presentation settings and Apple catalog, excluding Admin, JamfCheckIn, the normal update UI and background schedules. Its fresh policy is paused/dry-run. Installing it over full PUSH replaces reviewed YAML after backup and pauses PUSH monitors.

**The optional major-upgrade flow remains simulation-only. A live optional download/install/restart route is not enabled.** Full PUSH retains its existing managed required-update workflow. The demo never starts automatically.

## Set it up once

1. Install **PUSH Admin** on your IT workstation. Open **Guided Setup** and import existing policy or start a safe draft.
2. Review **Setup suggestions** for stable release tracking, hourly reminders, reminder-hour restrictions, deadline overrides, support contacts and prerequisites. Each proposed change is shown before applying it to the draft.
3. Add branding and preview popup buttons with simulated actions.
4. Open **Deployment → Build the complete client installer**. Choose paused installation or explicit live-monitor activation, then review the summary and select a new output folder.
5. Scope the exported profiles through MDM and provision required endpoint authorization/dependencies. Deploy the generated **one client package** to an approved pilot group.

The full-profile export contains the configured installer, profiles, reviewed YAML/images, instructions and a hash manifest. Major-only preview exports exclude MDM profiles and live activation. It needs no separate policy installer or activation script. The advanced split-package export remains available.

**Paused mode** installs the reviewed policy but leaves scheduling off. **Start monitoring after installation** requires dry-run off and an enabled macOS or registration policy. The installed schedules defer their first check for five minutes; subsequent live checks may notify, download, install or restart under that policy. A saved activation result reports which services loaded; this is not proof of an authorized or successful upgrade.

JamfCheckIn starts at the next graphical login, or users can open it after installation. Existing Jamf check-in/inventory administrator actions remain separate from PUSH’s guarded update requests. The former standalone PUSH Status menu is retired after backup. An Admin app left by an older combined installer is not silently deleted; remove it through your management workflow on employee Macs.

## What PUSH does

- **Ongoing discovery:** follow stable eligible releases, optionally staying within the current major version. Explicit YAML `update.deadline` overrides automatic deadlines from first discovery.
- **User awareness:** independent hourly toasts and full reminders, scheduling, restart prompts and truthful button results. Default fresh policy does not restrict reminders to work hours; sessions, meetings and installer activity can still delay delivery.
- **Deadline recovery:** saved failure reasons, Update now, persistent countdowns, guarded automatic retries, spacing and rolling daily limits. Credential/signature/state blockers do not get a false automatic bypass.
- **JamfCheckIn integration:** target, deadline, next toast, saved progress/failure and recovery countdown. User update requests are short-lived and bound to the console user and target; the root worker revalidates policy and safety. No end-user password fallback.
- **Admin tooling:** configuration editing, setup suggestions, catalog listing, safe popup/icon previews, deployment export and the configured client builder.
- **Readiness and history:** passive saved-state/service reporting and delivery evidence that distinguishes attempts, visibility, responses and failures.
- **Compliance wallpaper:** opt-in custom images, reassertion while below target and guarded restoration of the personal baseline.
- **Approved app updates:** opt-in Chrome, Firefox release and VS Code updates through a protected administrator-managed Installomator provider. Open apps are left running.
- **Registration reminders:** opt-in staged Entra nudges using current-user local evidence and the configured Self Service policy. No cloud-compliance claim; inactive on unenrolled Macs.

Admin’s setup suggestions are rules based on the draft and saved local evidence. Recommended defaults do not disable dry-run, enable automatic installation or clear an explicit deadline. A fresh draft/generic installation starts with automation off and dry-run on; imported or preserved policy must be reviewed separately.

## Permissions and prerequisites

Notification and exact-identity background-item profiles accompany exports for **MDM delivery**. They do not enroll a Mac, create bootstrap tokens or grant upgrade authorization. Optional uptime gentle restart uses a restricted System Events AppleEvents approval and requires a matching verified Developer ID-signed client; the local ad-hoc client cannot satisfy it. No broad Full Disk Access, Accessibility or Screen Recording grant is added.

Mist, a protected app-update provider, supported Self Service/Company Portal components and managed authorization remain separate prerequisites where selected. Admin workstation evidence does not certify the fleet. See the [deployment guide](docs/ADMIN-BUILDER-GUIDE.txt) and [profiles wiki](https://github.com/sebastiansantos1986/PUSH/wiki/Deployment-Profiles).

On a Mac with Xcode and its command-line tools:

```bash
bash Packaging/build-test-release.sh "$PWD/artifacts"
bash Tests/run-safe-tests.sh
bash PUSH-Admin/Tests/run-safe-tests.sh
bash JamfCheckIn/Tests/run-safe-tests.sh
```

For optional real package-builder fixtures (builds only; never installs):

```bash
PUSH_TEST_CLIENT="$PWD/artifacts/PUSH-Client-1.11.0.pkg" \
PUSH_TEST_BUILD_FOLDER="$PWD/artifacts/configured-fixtures" \
bash PUSH-Admin/Tests/run-safe-tests.sh
```

Choose a new fixture folder. These commands do not install packages or enable monitoring. Build outputs are excluded from Git. The source build needs no Developer ID identity for local test artifacts; production signing/notarization is separate.
