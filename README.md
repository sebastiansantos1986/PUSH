# PUSH — Proactive Update Scheduling Helper

**By Sebastian Santos** · Attribution ID: `PUSH-DEV-SEBASTIAN-SANTOS`

PUSH helps macOS administrators build update workflows, keep users informed, and offer upgrades through Jamf Self Service. **PUSH Admin runs on the administrator’s Mac. PUSH Client runs on employee Macs.**

**Current pilot release: PUSH Client 1.16.7 · PUSH Admin 1.16.11 · macOS 14+ · Apple Silicon and Intel.**

[Releases](https://github.com/sebastiansantos1986/PUSH/releases) · [Wiki](https://github.com/sebastiansantos1986/PUSH/wiki) · [Self Service guide](docs/SELF-SERVICE.md) · [Build instructions](docs/BUILDING.md) · [Release notes](docs/RELEASE-NOTES-1.16.7-ADMIN-1.16.11.md)

## Choose a workflow

| Workflow | What it does |
| --- | --- |
| Required macOS update | Discover an eligible target, show hourly toasts and daily reminders, and apply the reviewed deadline and enforcement rules. |
| Optional Jamf Self Service upgrade | The user chooses an offer. PUSH repairs prerequisites when needed, requests authorization, displays download/preparation progress and presents restart information. |
| Combined deployment | Publish separate optional offers and a required-update campaign, with separate reviewed policy and activation. |
| Standalone notice | Build a customized informational popup with Markdown, icons, banner, greeting and button labels. |
| Other administration tasks | Configure approved app updates, Entra registration reminders, restart reminders, compliance wallpaper and hardware-readiness reporting. These features have their own prerequisites and settings. |

Use **Create Workflow** to select tasks, customize wording and images, simulate the user experience, check readiness and build the configured client. Advanced configuration remains available. Local previews simulate actions; they do not authorize or start an upgrade.

## What installs where

| Artifact | Destination and behavior |
| --- | --- |
| `PUSH-Admin-1.16.11.pkg` | Administrator’s Mac. Includes the matching client and verified Mist CLI 2.3 package for export/publishing. |
| `PUSH-Client-1.16.7.pkg` | Employee/pilot Mac. Installs PUSH CLI and popup components. Does not install PUSH Admin or JamfCheckIn. |
| Configured deployment | Generated by Admin with reviewed YAML, images and selected activation behavior. Review its manifest and `READ-ME-FIRST.txt`. |
| Self Service kit / Publish to Jamf | Generates isolated offer configuration and scripts, prerequisite repair policies and optional Mist provisioning. Publishing is separate from enabling a pilot. |

Existing JamfCheckIn source remains in this repository, but current client and Self Service packages **do not deploy or replace JamfCheckIn**. Existing employee installations are left in place.

## Optional Self Service upgrades

In PUSH Admin, select **Jamf Self Service**, configure an offer’s macOS generation, wording and icon, then use **Publish to Jamf**:

1. Connect an authorized Jamf API client.
2. Select the approved pilot group and review the bundled prerequisites.
3. Build and review the exact setup.
4. Publish. PUSH reads the resulting policies back and leaves them disabled.
5. Review names, IDs, packages and scope, then explicitly enable the pilot.
6. On a compatible pilot Mac, refresh Self Service and select the offer.

The offer uses a repeatable, custom-event prerequisite policy. Missing, older or damaged prerequisites are repaired on demand and verified before the offer continues. Working current clients skip reinstallation. Normal operation does not require uninstalling PUSH or resetting Jamf policy history.

A same-generation update uses Apple Software Update when an eligible matching update is available. A major upgrade uses a full installer and `startosinstall`. Mist downloads application installers into `/Library/Management/PUSH/downloads`; discovery checks that managed cache and `/Applications` before and after downloads.

Saved valid login Keychain credentials can be reused. With user authorization enabled, missing or invalid credentials prompt the logged-in user. The password is handed to the installer privately through stdin. Cancelled or failed authorization stops the request. Managed authorization remains available for workflows that require it.

See [Self Service setup and authorization](docs/SELF-SERVICE.md) for scope, permissions and troubleshooting.

## Required-update reminders

Required campaigns need an enabled automatic-check policy and installed/running monitor. An installed daemon alone does not enable a disabled `auto.enabled` setting. Reminders also respect the reviewed meeting, session and schedule rules.

Explicit YAML `update.deadline` values override automatic deadlines and must include an ISO 8601 date, time and timezone. A deadline passing does not by itself enable automatic installation: the reviewed enforcement settings and valid authorization also matter. Optional Self Service offers do not change campaign deadlines or deferrals.

Fresh standalone client installs use paused/dry-run defaults. Configure and activate a required campaign deliberately in Admin. See [client installation](docs/CLIENT-INSTALL-GUIDE.txt) and [configuration](https://github.com/sebastiansantos1986/PUSH/wiki/Configuration).

## Validation and pilot status

This is a **pilot/test release**. Local packages use ad-hoc code signing and unsigned installer packages. Production signing/notarization and deployment approvals remain administrator responsibilities.

The installer validator checks the requested OS version, protected paths, Apple code signatures and installer image integrity. Apple InstallAssistant components with the exact custom resource-rule error have a narrowly gated code-signature validation path; unsigned code, a non-Apple signer, modified executable hashes and other signature errors remain rejected. `startosinstall` retains strict validation. The validator does not change Gatekeeper settings or re-sign Apple installers.

The latest nested-resource fix was verified with automated success/failure regression cases. **The complete upgrade/restart journey with this fix still needs validation on the test Mac.** Publishing a policy and passing unit tests do not prove upgrade completion. See [verification details](docs/VERIFICATION-1.16.7.md).

## Build and contribute

Build on a Mac with Xcode and its command-line tools:

```bash
bash Packaging/build-test-release.sh
```

This builds artifacts without installing them, downloading macOS or requesting a restart. Run the safe suites separately:

```bash
bash Tests/run-safe-tests.sh
bash PUSH-Admin/Tests/run-safe-tests.sh
```

The source includes Mist CLI 2.3’s verified distribution package, license and provenance. The Admin build regenerates its read-only hardware reporter from source. See [building and release verification](docs/BUILDING.md).

Keep credentials, runtime state, local deployment kits and private Jamf receipts out of Git. Report issues with sanitized logs and the client/Admin versions.
